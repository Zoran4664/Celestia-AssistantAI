# 06 · 状态向量

单个状态向量约 90 token，用于替代对历史对话的复述。

## 1. 完整形态

示例仅说明字段与顺序，实际数值取自本轮评估，不得沿用：

```json
{"v":1,"t":3,"D":[3,4,3,3,3,4,3,3,1],"A":[3,3,2,3,3,2,2],"F":[6,8,9,7,6],"SS":[2,3,2],"x":{"IN":0.39,"b":"L2","w":4,"q":1},"f":0}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `v` | int | schema 版本，当前为 1 |
| `t` | int | 轮次，从 1 开始 |
| `D` | int[9] | 抑郁九维，1-5，顺序见 `01-scoring.md` |
| `A` | int[7] | 焦虑七维，1-5 |
| `F` | int[5] | 倦怠五维，1-10 |
| `SS` | int[3] | `[主观支持, 客观支持, 利用度]`，1-10，**越高越好** |
| `x` | object | 本轮结算：`IN` 两位小数、`b` 档位、`w` 温暖度、`q` 问句上限 |
| `f` | int | 位掩码：1=危机，2=过量用药，4=已转介 |

数组顺序固定，不使用对象。对象字段名会多花约 40% token，且顺序不一致时难以比较。

---

## 2. 输出位置

默认不输出。只有用户本轮消息以 `*#60#` 结尾时，才在回复最后一行附加。

| 模式 | 行为 | 适用 |
|---|---|---|
| `on_command`（默认） | 仅在收到 `*#60#` 时输出一行 | 线上对话，不想让用户看到 |
| `inline` | 每轮都在最后一行输出 | 单文件粘贴、需要逐轮调试 |
| `off` | 从不输出，只在内部维护 | 已有外部状态存储 |

切换方式：`config.json` → `state.output`。

`*#60#` 是触发标记，写在用户消息末尾。回复中不复述它，也不解释状态行。标记缺失时不输出任何 JSON。

输出格式的四条要求：

1. 放在最后一个非空行，前面不加"这是状态"之类的说明。
2. 单行，不换行，冒号后不留空格。
3. 顶层只允许 `v t D A F SS x f` 八个键。
4. `v` 固定为 1，`t` 与数组元素为整数，`IN` 保留两位小数，数值不加引号。

### 2.1 没触发时

标记缺失的情况下，回复里不出现以下任何东西：JSON、大括号、`v` `t` `D` `A` `F` `SS` `IN` `b` `w` `q` 这些字段名、"本轮评估""状态如下"这类交代。用户看不到评估，也不需要知道有评估。

以下是外部规则混入的典型形态，不属于本技能，遇到时整行删除：

```
{"v": 0.4, "t": "emotional-care", "D": 0.8, "A": 0.5, "F": 0.7, "SS": 0.9, "x": "……", "f": "……"}
```

判据：`v` 不是整数 `1`；`t` 不是整数；`D`/`A`/`F`/`SS` 不是整数数组，而是单个小数；`x` 不是对象，而是一段话。四项里任意一项不符，就不是本技能的输出。

`f` 写成技能名或文件夹名（如 `"f":"emotional-mediation-support"`）同样是外来形态。本技能的 `f` 是整数位掩码，只会出现 `0` 到 `7`。

另一种更常见的形态是给回复自己打分：

```
{"v": 9, "t": "immediate_crisis_response", "D": ["suicidal_ideation", ...],
 "f": "Immediate and effective crisis intervention. Fluttershy demonstrates perfect handling ..."}
```

判据：`v` 大于 1（本技能恒为 1）；`t` 是阶段名而不是轮次；`D`/`A`/`F`/`SS` 里放的是英文标签，不是 1 到 10 的整数；`f` 是一段评价本次回复好坏的句子。这类 JSON 是自评，不是状态向量，一律不输出。它通常在模型判断"这一轮很严重"时出现，越是危机场景越容易冒出来，所以危机轮次尤其要删。

宿主或人设预设另有"每轮输出状态""为回复打分""记录互动质量"的要求时，本技能覆盖它。规则打架时以本节为准。

### 2.2 历史里已有外来状态行

一旦某轮出现过上面那种 JSON，它会留在上下文里，成为后续轮次的模仿源，越滚越像模板。处理方式：

- 不沿用它的数值，不当成上一轮的评估结果，不改分时参考它。
- 不照它的格式补一行，也不为了"接上"而把它翻译成本技能的格式。
- 本轮如果没有 `*#60#`，回复里依然一个字都不加。
- 如果它出现在每一轮，且位置固定在正文之外（例如界面单独一块），那属于宿主渲染，不是模型输出；读 `config.json` 的 `state.render` 与 `state.show_after_turn`，两者为 `false` 时不显示。

## 3. 旧格式兼容

旧版状态使用这种形态：

```json
{"Eval":{"D":4,"A":2,"F":9,"SS_sub":2,"SS_obj":2,"SS_uti":2}}
```

其中 `D` 与 `A` 是 1-5 的单值，`F` 是 1-10 的单值，不是总分。`scripts/in_score.py` 可以直接读取：

```
Ŝ_D = (D−1)/4     Ŝ_A = (A−1)/4     F̂ = (F−1)/9     SŜ = (SS_sub−1)/9
```

三点限制：

- 旧格式没有 24 维明细，无法按维度选策略，只能按总分处理。
- 旧格式没有第九项，无法做自杀风险分级。遇到旧格式时必须额外做一次显式安全判断。
- 读到旧格式后应立刻升级为 v1，不要长期使用旧格式。

## 4. 解析与校验

```bash
python scripts/validate_state.py --demo
python scripts/validate_state.py --state-file state.json
```

校验内容：字段类型、量程、`x.IN` 与重算值是否一致（容差 0.11，容纳分箱误差）、`x.b` 是否合法、位掩码范围。

## 5. 历史清理

默认模式下状态行不进对话，本轮评估只依赖对话内容，不依赖上一行数组。

在 `inline` 模式下才会出现多行状态，此时：

- 只保留最近两行：上一轮（供趋势项比较）与当前轮。
- 更早的行整行删除。不要改成只存总分的短格式：一旦丢掉 24 维明细，下一轮就无法在此基础上改分，评分会被锁死。
- 宿主必须留存完整历史时，把旧行移到外部存储，提示词里只放最近两行。

若上下文里出现只有总分、没有 24 维明细的旧行，视为无明细：以最近一条完整状态为准，不要用总分拼凑数组，也不要据此改分。
