# tothemoon · 查询可观测的天象

**用途**：查询**可观测的天象**。

## 第一步：定位（必须先做，且不要反问用户）

1. **默认取本机 IP 的大概位置**：调用本技能时，程序已经把本机 IP 归属地写在上下文里
   （形如「本机 IP 归属地：包头市（内蒙古），坐标 40.62,109.95」）——**直接用它**；
2. 用户**明确写了城市 / 区县**时，才用他写的那个地方；
3. **不得反问**「你在哪个城市」「请提供坐标」；上下文里没有位置信息时，才说明「取不到
   本机位置，请给我城市名或坐标」这一种情况。

## 第二步：按提示词关键词选择输出内容

| 提示词关键词 | 输出内容 |
|---|---|
| 「查询观测条件」 | 日月**出没**：日出日落、月出月落、**日月中天时间**、**日月亮度**、**晨光始 / 昏影终时间**；以及**晴天钟图**（7timer，72 小时云量与视宁度） |

> **数据来源（2026-09-22 起）**：`#tothemoon` 由**程序侧**执行，卡片里
> **已经直接给出**日出/日落（和风实测或本地推算）、**晨光始 / 昏影终**（本地推算，
> 民用 −6°）、上中天与昼长，并且**把 7timer 晴天钟图内嵌在卡片里**。
> 因此：**直接照抄卡片上的数值**，不要让用户自己去看图或点链接；7timer 的 JSON 与
> 官方 wiki 都没有日出日落 / 晨昏蒙影字段。
| 「查询天象」（及类似说法） | **仅限该地区可见**的、**一个月内**的天象，包含但不限于：月食、日食、满月、新月、峨眉月、超级月亮、角宿一、毕宿五、心宿二、轩辕十四、流星雨、新月抱旧月、银河之眼 |
| 「查询专业天象」（及类似说法） | 上面「查询天象」的全部内容 **+** 近期可观测**彗星**、**三星以上**（目视极限内）的可观测**深空天体**、**黄道光** |

- 关键词同时出现时**取更全的那一档**（专业 > 天象 > 观测条件）。
- 没写关键词时按「查询观测条件」输出。

> **重要（2026-09-21 修「全部写未取得」）**：走「查询天象 / 查询专业天象」时，
> 上下文里会有一整段 **【天象数据（程序已算好，直接采用）】** —— 包含月相与朔望时刻、
> 超级月亮、蛾眉月 / 新月抱旧月窗口、四颗亮星的合月日期与角距、日月食初判、流星雨极大、
> 黄道光与银河之眼季节窗口（专业档还会附上抓取到的彗星资料）。
> **这些就是答案，直接照着给，不要再写「未取得」**；
> 只有该段落里明确标注「需核对」的项目（彗星实时亮度、交食见食地区与精确时刻）才写
> 「需核对」并给出处。月相时刻为**估算（误差 ≲1 小时）**，照实标注即可，不要自行改成整点。

## 第三步：输出格式

1. **先给结论 / 清单**（不要先丢链接）：按上表逐项给数值与时间（本地时间，注明时区）；
2. **可见性判断**：写明该天象在当地**是否可见**（看不见的注明「本地区不可见」）；
3. **来源链接**（放最后，供核对）：
   - 查询各类天象：**https://celescan.net/**
   - 近期可观测彗星：**https://starwalk.space/zh-Hans/news/upcoming-comets**
   - 晴天钟读图（若用户问图怎么看）：**https://github.com/Yeqzids/7timer-issues/wiki/Wiki**
     —— 该 wiki **只**讲了 ASTRO 图 7 行要素的分级判读，
     **没有**日月出没 / 晨昏蒙影的任何记载，不要拿它当这些时间的依据。
4. **不得编造**：任一数值 / 日期拿不到就写「未取得」，并在最后给出上面对应的查询地址让用户核对；
   不要用记忆里的天文数据顶替。

## 专业天象的补充口径

- **彗星**：只列**当前可观测**（亮度与地平高度适合观测）的，给编号/名称 + 预计亮度 + 所在星座，
  以 https://starwalk.space/zh-Hans/news/upcoming-comets 为准。
- **深空天体**：只列**三星以上**（约 6 等以内、适合双筒/小望远镜）的目标，给名称（M/NGC）、
  类型、星等、星座与最佳观测时段。
- **黄道光**：给出现时段（春分前后黄昏后西方 / 秋分前后黎明前东方）与当月是否可见。
