# 晴天钟（7timer）：图 / JSON / 图例

> 官方说明（图怎么读、晨光始与昏影终等）：**https://github.com/Yeqzids/7timer-issues/wiki/Wiki**

## 图（PNG）

| 用途 | 地址 |
|---|---|
| 天文 / 观星图（云量、视宁度、透明度、风、温湿、日月出没与晨昏） | `https://www.7timer.info/bin/astro.php?lon=<经度>&lat=<纬度>&ac=0&lang=zh-CN&unit=metric&tzshift=8` |
| 一般气象图 | `https://www.7timer.info/bin/civil.php?lon=<经度>&lat=<纬度>&ac=0&lang=zh-CN&unit=metric&tzshift=8` |
| 同一张图的 JSON | 在上面地址末尾加 `&output=json` |

- `tzshift=8` = 北京时间（其它时区按 UTC 偏移填）。
- 实测（2026-09-21）：图片返回 `image/png`；JSON 返回 JSON（`Content-Type` 有时写 `text/html`）。
- **重要（2026-09-22 核对官方 wiki）**：该 wiki **只**说明了 ASTRO 图的 7 行要素
  （云量 / 视宁度 / 透明度 / 降水概率 / 大气不稳定度 / 潮湿警告 / 大风警告）与 API
  数值图例，**完全没有**日出日落、月出月落或晨昏蒙影的记载；7timer 的 JSON 里也
  **没有**这些字段。所以：

  | 数据 | 来源 |
  |---|---|
  | 云量 / 视宁度 / 透明度 / 风 / 温湿 | 7timer JSON（`&output=json`） |
  | **日出 / 日落 / 晨光始 / 昏影终 / 上中天** | **本程序本地推算**（`sky_service.sun_times`，NOAA 简化式，误差 ≲1 分钟） |
  | 月相 / 月出月落 | 和风天文接口（需配 KEY；没配就只给太阳时刻） |

  口径：日出日落取太阳上边缘相切地平线（天顶距 90.833°）；
  晨光始 / 昏影终为**民用晨昏蒙影**（太阳高度 −6°，天顶距 96°）；
  上中天为真太阳时正午。**不得**再写「以 wiki 为准」或让用户自己去看图。

## JSON 结构

```json
{ "product": "astro", "init": "2026092012",
  "dataseries": [ { "timepoint": 3, "cloudcover": 1, "seeing": 3, "transparency": 2,
                    "lifted_index": 2, "rh2m": 4, "temp2m": 20,
                    "wind10m": {"direction": "SE", "speed": 2} } ] }
```

- `init` 是模式起报时刻（**UTC**，`YYYYMMDDHH`）；`timepoint` 是相对起报的小时数，3 小时一档；
  本地时间 = `init(UTC) + timepoint + tzshift`。
- `dataseries` 约 72 条（≈9 天），前 8 条 ≈ 未来 24 小时。
- `wind10m.speed` 单位 m/s，`direction` 为 16 方位缩写。

## 结论口径（程序侧 `sky_service.summarize`）

窗口 = 未来 24 小时（8 格）；单格「可用」= 云量 ≤3 且视宁度 ≤4：

| 结论 | 条件 |
|---|---|
| 不适合 | 云量中位数 ≥7 或最好一格 ≥6 |
| 适合 | 存在连续两格可用且云量中位数 ≤4 |
| 勉强 | 其余 |

最佳时段 = 平均云量 + 平均视宁度最小的连续两格（比**平均**而非总和，否则末尾单格永远胜出）。
