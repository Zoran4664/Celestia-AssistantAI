FTS 在线解析 / SOHO-CCOR 彗星同星判断**。

> **重要（2026-09-21 修「说查不到」）**：直接调用 `#tothestars` 时，**程序会先取数**并把
> 结果放进上下文里的一整段 **【巡天核查（程序已查好，直接采用）】** —— 包含：
> 目标坐标（时角式 + 十进制，换算已做）、**① NOVA（Rochester）±10″ 比对结果（命中条目或
> 「未命中」）**、**② VSX 10 角分检索结果（**双源互验**：VizieR + 官网，含
> Dist.'/Name/Coords/Var. type/Period/Mag. range/AUID/星座/来源 与详情页网址）**、
> **③④⑤ TNS / ALeRCE / CDS 三条网址（编码已由程序生成）**。
> **这些就是答案，直接采用、原样输出，不要再写「我核查不了 / 无法判定」**；
> 只有标注「需核对」或该段落缺数据的项才照实说明并给出处。
> SOHO/CCOR 同星判断与 FTS 解析仍按下面 3、4 节由你完成。

全局规矩（四条都必须遵守）：
1. **先拿坐标**：用户给的可能是 `23:47:06.00 +29:29:17.3`、`23 47 06.00 +29 29 17.3`、
   `18 46 08.16 +58 59 15.6` 或十进制度度；程序会统一换算并写进上下文（两种写法都有）。
2. **只输出链接的地方绝不代查**：TNS / ALeRCE(ZTF) 有反机器人机制，程序代查易失败，
   因此这两处**只给可点击网址**（程序已生成好，原样输出），并写明「请点开自行查询」。
3. **坐标 / 时间一律按用户给的原文**，不要自行四舍五入成别的值；乘除换算后要回代校验。
4. **查不到就说查不到**，不要用记忆猜天体类型、星等或发现者。

## 1. 已知瞬变天体（超新星 / 新星）核查

触发：提示词带 RA/DEC 并问「是不是已知瞬变天体 / 超新星 / 新星」。

按顺序给四类结果：

### ① NOVA（Rochester）— 程序已比对，±10″ 内算命中
- 站点：https://www.rochesterastronomy.org/novae.html
- **程序已抓取该表并按目标坐标 ±10″ 比对**（球面角距），结果在上下文【巡天核查】段：
  命中 → 逐条输出**可能的新星**（名称、坐标、角距、星等）+ 站点链接；
  未命中 → 如实写「Rochester 未命中（弱结论，不代表不是新星）」+ 站点链接
  https://www.rochesterastronomy.org/novae.html

### ② TNS — **只输出链接**
- 程序已按模板生成好网址（在上下文【巡天核查】段）→ **原样输出**，不要再自己拼编码。
- 模板（radius=10，单位 arcsec）：
  `https://www.wis-tns.org/search?ra={RA}&decl={DEC}&radius=10&coords_unit=arcsec&include_frb=1`
- 例（`23:47:06.00 +29:29:17.3`）：
  https://www.wis-tns.org/search?ra=23%3A47%3A06.00&decl=%2B29%3A29%3A17.3&radius=10&coords_unit=arcsec&include_frb=1
  （`%3A` = `:`，`%2B` = `+`）
- 说明：TNS 有反机器人机制，程序代查容易失败 → **只给链接让用户点开自查**。

### ③ ZTF（ALeRCE）— **只输出链接**
- 程序已按模板生成好网址（RA/DEC 为十进制度，radius=50）→ **原样输出**。
- 模板：
  `https://alerce.online/?ranking=1&ra={RA_deg}&dec={DEC_deg}&radius=50&count=false&page=1&perPage=20&sortBy=probability&sortDesc=true`
- 例（`12 11 11.11 +15 14 14.3` → RA=182.79629166666666，Dec=15.237305555555555）：
  https://alerce.online/?ranking=1&ra=182.79629166666666&dec=15.237305555555555&radius=50&count=false&page=1&perPage=20&sortBy=probability&sortDesc=true

### ④ CDS 星图
- 程序已生成好网址（在上下文里）→ 原样输出。
- 模板：`https://portal.cds.unistra.fr/?target={RA}%20{DEC}`（`%20` = 空格，`%2B` = `+`）
- 例（`23:47:06.00 +29:29:17.3`）：
  https://portal.cds.unistra.fr/?target=23%3A47%3A06.00%20%2B29%3A29%3A17.3

**输出顺序**：① 可能新星（若有）→ ② TNS 链接 → ③ ZTF/ALeRCE 链接 → ④ CDS 星图链接
→ 一句「以上为自查链接，未查到即不能判定为已知天体」。

## 2. VSX 已知变星查询

触发：提示词说查变星 / 是不是已知变星。

- **程序已按 10 角分半径、双源互验检索 VSX**（2026-09-23 起）：源① **VizieR `B/vsx`**
  （服务端按角距升序返回，最近的那几颗不会再被截断）＋ 源② **VSX 官网 `query.votable`**
  （定期镜像之外的最新数据，多出 AUID 与星座）。**两个源任一命中即算命中**，
  程序已合并去重，并在每行末尾标注来源：`[VizieR/官网]` = 两源都有；
  只标 `[官网]` 的 = VizieR 镜像尚未收录（正是「小项目新命名」那类），**同样算命中**。
- 结果在上下文【巡天核查】段 → **逐行原样输出**，每行字段：
  `Dist.' / Name / Coords (J2000) / Var. type / Period (d) / Mag. range / AUID / 星座 / 来源 / 详情页网址`
  （AUID 为空表示该条目没分配 AUID，写「—」即可；星座已由程序给出，不必再让用户查。）
- **第一行通常就是目标坐标处那颗（`Dist.' ≈ 0.00`）**，必须先把它写出来，
  不要只报角距更大的条目 —— 这是修过的老 bug（曾因取数截断而整条漏掉）。
- 详情页地址规则：`https://vsx.aavso.org/index.php?view=detail.top&oid=<真实数字 OID>`；
  **只允许 `vsx.aavso.org`**（`www.aavso.org/vsx/...` 实测 403），
  OID 拿不到时才给检索页 https://vsx.aavso.org/index.php?view=search.top
  （用法：坐标填 **Position**、格式选 **Sexagesimal**、**Size = 10 arc minutes**）。
- 没命中 → 明确说「VSX **两个源都**未命中」，不要猜变星类型。

## 4. SOHO / CCOR 彗星：判断是不是同一颗

触发：给了**两个及以上**目标，问「是不是同一颗」。

- **判据**：CCOR/SOHO 彗星速度近似，**相同时间间隔内 X/Y 方向移动距离也应接近** →
  比较「同一时间跨度内 X、Y 的位移」是否一致（允许小幅误差）。
- **输入格式**（都要能识别）：
  - `1215 1650 1385` = **时分, X, Y**
  - `CCOR2_1A_20260918T191514_V00_NC_processed.fits: (645, 395)`
    → 取 `191514` 里的**时分即 1915**，`2026` 年 `0918` 月日（有时候不写年月日），
    括号内 `(645, 395)` = **(X, Y)**
  - `18:15:25 689 345` = 时分秒 + (X, Y)，同样**只比时分与 X、Y**
- **判断次数**：
  - 所有目标**都给了年月日** → 只判断一次（同一天是否为同一颗）；
  - 只要有**任何一个**没给年月日 → 输出**三次判断**：
    1. 同一天的情况下是不是同一颗；
    2. A 在前一天、B 在后一天，是不是同一颗；
    3. B 在前一天、A 在后一天，是不是同一颗。
- 输出：每次判断给「是 / 不是 / 无法判断」+ **依据**（ΔX、ΔY 与时间差），
  不要含糊其辞。
